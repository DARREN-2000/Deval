Why Deval?

Engineering quality is fragmented across dozens of tools. Deval unifies them into a single, understandable metric.

Deterministic, not probabilistic

No model sits in the loop. The same commit always produces the same score. Rely on it to gate builds without flaking.

One score from many tools

Findings from Ruff, Semgrep, Trivy, and Gitleaks are normalised, de-duplicated, and folded into a single number.

Every rule explains itself

Each rule carries a stable DV code with problem, rationale, example, and fix. deval explain prints all of it.

Standards you can layer

Global → Recommended → Domain → Organization → Repo. Nothing is applied silently.

Rules are just functions

Write a rule with a simple Python decorator. No complex subclassing, no massive framework to learn.

Adoptable on day one

Baselines freeze existing debt so a large codebase can enforce standards on new work without a massive rewrite.

How it Works

A fast, transparent pipeline from code to score.

1. Auto-Detect

Deval scans your repo and instantly identifies the language, framework, and infrastructure.

2. Evaluate

Runs native checks and integrates external tools based on your specific stack.

3. Score

Deduplicates findings and calculates a deterministic score across 13 engineering dimensions.

4. Report

Outputs to Terminal, SARIF for GitHub Advanced Security, HTML, or JSON.

# Install from PyPI
pip install deval

# Score the repository you are standing in
deval scan .

# Machine-readable output for CI and code scanning
deval scan . -f sarif -o deval.sarif
deval scan . -f json  -o deval.json

# Understand any rule, with rationale and a fix
deval explain DV6003
# Scan the current directory, read-only, as a non-root user
docker run --rm -v "$PWD:/repo:ro" ghcr.io/darren-2000/deval:latest

# Any subcommand works
docker run --rm -v "$PWD:/repo:ro" ghcr.io/darren-2000/deval:latest   scan . -f markdown

# Pin a version for reproducible pipelines
docker run --rm -v "$PWD:/repo:ro" ghcr.io/darren-2000/deval:0.6.0
# .github/workflows/deval.yml
name: deval
on: [push, pull_request]

jobs:
  standards:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      security-events: write
    steps:
      - uses: actions/checkout@v4
      - uses: DARREN-2000/deval@v1
        id: deval
        with:
          path: .
          min-score: '80'
          upload-sarif: 'true'
      - uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: report.sarif

      # Outputs: score, grade, passed
      - run: echo "Scored ${{ steps.deval.outputs.score }}"
# Fail the build below a score, or on any error-level finding
deval scan . --min-score 80 --fail-on error

# Adopt gradually: freeze today's findings, block only new ones
deval baseline .
deval scan . --baseline .deval/baseline.json

# Check config and tool readiness before you rely on it
deval doctor .
